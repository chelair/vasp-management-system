# 操作日志与个人经验

2026-10-26：最小版已实现。复用原审计、原AI连接和工作台工具，不另建执行器，不训练模型权重。

## 现在的工作方式

1. 关键任务操作沿用 `data/audit/actions.jsonl`。补充事件ID、操作者ID、任务操作的HTTP结果、参数实际写入前后差异、草稿内容、归档/恢复状态。账号日志和自动化日志继续兼容原格式。草稿、写入输入、提交受理与计算完成分别解释，不把一次操作总结成通用规律。
2. 每个启用账号每个自然周自动整理一次；使用其本人选定的已有模型连接。仅采集最近7天本人在当前有权访问任务中的操作，排除账号认证、其他用户和自动化操作。每次最多40条、16000字符输入、2048输出token、8条候选经验；一次请求，不自动重试。每周可手动补试一次，失败/空结果也计入次数，避免反复消耗模型额度。
3. AI必须给出同一项目中真实存在的来源事件ID，否则不入库。经验初始为“待核实”，保存冻结操作摘要与来源；模型不补造动机、计算结果或因果关系。首版没有自动关联完整优化过程来验证某个参数改动是否起效，结果缺失时保持未知。
4. 工作台新增“操作经验”：看最近100条本人操作和50条经验、修改/确认/停用经验、下载Markdown知识文档、选择整理连接与关闭周整理。修改由本人进行；停用立即从检索与文档排除。
5. 模型通过 `search_work_experience(query)` 按需检索，最多5条。使用英文词/中文双字关键词匹配，当前项目优先；也可参考本人其他当前可访问项目的经验，须核对体系和适用条件。当前用户指令和实时计算证据优先，经验不授予任何提交/执行权限。没有另外引入向量服务。

## 文件与空间

- 统一追加/轮转锁，避免账号、人工与自动化审计在截断时互相丢写。JSONL达到16 MiB时先轮转，每周压缩；压缩日志保留28天且总量最多64 MiB。活动日志以外的轮转文件在周维护时清理。
- 旧 `audit_submit.log` 每周折叠到 `data/audit/submission_counts.json` 后清空；保存已计数的文件前缀指纹，异常中断后重试不重复计数。仪表盘合并累计数与新日志，历史提交统计保留。
- 经验存 `data/ai/work_experience.sqlite3`，文件权限600，SQLite最大约64 MiB，每人最多1000条；超过上限停止新增并显示错误，已有经验继续使用。首版不自动删除已确认知识。
- 每人一份 `data/ai/work-experience/<用户ID哈希>/experience.md`，原子更新，不放进共享 `knowledge/`。经验与检索先按本人和当前项目权限过滤；模型连接密钥不进入学习材料。
- 原始日志有保留期；经验中的来源是整理时冻结的操作摘要，不声称完整原始日志永久可回溯。

周维护复用原巡检调度线程，每小时做一次轻量到期检查，首个到期检查补做本周任务，时间口径为Asia/Shanghai。整理失败显示错误，未完成的模型请求在服务重启后标记中断，不自动补发。其他账号默认不启用模型整理，普通操作审计照常记录。

## 接口

均在原私有工作台 `/api/ai/chat` 下，继续使用登录鉴权、no-store及本人连接归属校验：

| 方法与路径 | 用途 |
| --- | --- |
| GET `/work-experience` | 本人设置、最近经验/操作、Markdown文档 |
| PUT `/work-experience/settings` | `{enabled, connection_id}` |
| POST `/work-experience/learn` | 本人手动整理，计入每周两次上限 |
| PUT `/work-experience/{id}` | 修改title/body/confirmed/disabled，不允许改owner、项目或冻结来源 |

验证限于4项新专项：日志轮转与累计数/中断重试、Mock模型HTTP整理与中文检索/本人隔离、修改停用、伪来源拒绝和周任务去重；另回归5项创建输入/归档用例。类型检查、工作台抽屉轻量检查与临时构建用于发布确认，不运行全套测试，不触发HPC操作。
