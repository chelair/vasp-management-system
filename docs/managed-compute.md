# 项目托管：当前能力和执行缺口

维护日期：2026-10-20。M0 源码 `34e3801` 已随 v1.1.4 发布；这是计划、排序和资源/脚本预览阶段，**没有接通项目计划的自动执行**。原单 OPT 执行能力见 [执行说明](execution.md)。

## 已有能力

- AI 工作台可保存项目目标、阶段交付时间、任务级优先级及资源偏好，支持口语/模型别名；真实歧义再问用户。
- `managed_plan.py` 原子保存 `data/managed_plan.json`（schema `managed-plan.1`），带 revision、最近历史及原 automation 审计；人工锁定不被 AI 覆盖，结束计划只允许人工。
- `managed_schedule.py` 先排任务，再枚举资源。优先级取任务覆盖、阶段设置或默认值，同级考虑交付日期。ready、需续算、排队/运行分别列明，排序不等于已经提交。
- 队列允许/禁用、付费偏好、节点/核数/walltime/核时/提交上限已可保存。资源在真实新鲜快照中硬过滤后确定性评分，给出分项/理由；模拟、过期和缺失快照返回 blocked。
- `vasp_script.py` 按前端八段模板渲染，只预览、不写远端；`test_vasp_script.py` 有模板漂移核对。
- 前端入口已并入**自动化页 `/automation`**，默认“项目托管”、另一标签“自动化规则”，目前均只对管理员开放；`6a6fe24` 已发布，原 `/managed` 独立页/菜单移除。后端项目归属鉴权不变；托管面板保留人工优先级/锁定、暂停/恢复/结束、资源建议和脚本预览。

## 接口和工具

`GET /api/managed`、`POST /api/managed/plans`；`GET/PATCH /plans/{id}`；`POST /plans/{id}/status`；`GET /plans/{id}/candidates`、`resource-plan`、`script-preview`。用户仅能读写本人授权项目，PATCH 带 revision，冲突 409。

AI 工具为 `get_managed_plans/create_managed_plan/update_managed_plan/set_task_priority`。它们只能写计划/优先级，不提交或停止计算。字段边界以 `managed_tools.py`、`managed_plan.py` 和 API 为准。

计划 active、候选有 action、资源有高分、执行总开关开启，都不能单独证明 M0 已会自动运行。当前没有从项目计划到巡检后执行的接线。

## 仍需接通的最小链路

用户目标/期限/偏好 → AI 保存业务计划和规则 → 每轮巡检完成后对账并收集授权 ready 任务 → Python 识别场景 → 普通动作零模型调用、异常少量 AI 选择 → 按任务优先级分配资源 → 确定性脚本 → 原续算/提交核心 → 下轮验证。

以下缺口从原审视保留，不再另存一份重复审计：

1. 巡检目前逐任务即推进；需整轮候选仲裁，并扫描被全局巡检跳过的 pending 首提任务。
2. 运行中 ACTIVE 早返回，受力振荡/停滞、累计多日且多次续算无改善、报错等尚未接成规则分流；识别不能依赖模型。
3. AI 当前只审阅唯一 OPT 候选；需能在后端给出的可行动作/范围中真正选择下一步，保存简明原因，不发送完整报告/历史日志。
4. 模型调用不要阻塞事件消费；增加同一异常事件去重、冷却、每轮调用/证据预算，不为普通等待反复花 token。
5. 旧授权单队列、旧预算脚本解析和脚本不变校验，与多队列资源择优不兼容；不能认为 M0 预览已修好旧执行面。
6. 观察/提交/修复次数分账，正常 walltime 接力不应消耗异常 repair；托管寿命不依赖用户浏览器会话一直有效。
7. 旧自动化与新托管一个任务只能有一个执行归属。资源预留覆盖同轮竞争和现有人工作业，避免多个任务同时选走相同额度。
8. 暂停托管与停止 HPC 作业分开；停止在授权内复用旧入口，确认 LSF 终态后才能重提。运行中作业不擅自迁队列。
9. 软 STOPCAR 结束、常见固定原子判力和输入适用范围需实测接通；未知证据不当失败盲重算。

先支持已有模型/输入的任务顺序和 OPT 续算，不自动建模或搭完整 OPT→STATIC→DOS 输入工作流。不把队列 PEND/空闲核数称为精确等待时间，不假定更多核必然更省核时。
