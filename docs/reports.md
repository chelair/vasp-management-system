# 科研报告与可复用元素

维护日期：2026-10-31。本文件合并 R1/R2/R4、PMS 空草案修复、报告审阅和简明报告说明；性质公式与接入规则见 [科学分析规范](../ANALYSIS_FEATURES.md)。接口细节见 [API](../API.md)。

## 用户的默认使用路径

用户一句话 → 原 AI 会话理解语义/找数据 → Python 确定性计算 → 选择已有报告元素 → 保存独立专题 → 查看、编辑和导出。

报告保存后，AI工具同时返回实际展示的正文，供核对；再次读取会得到当前有效的结论、建议与人工编辑。`list_topic_reports`查询本人当前项目的报告，`get_topic_report`读取正文和冻结数据，按图表编号可读取DOS等原始曲线，`update_topic_report`修改同一报告；本人同项目的新对话可复用原报告，不复制ID或移动原对话。默认正文4000字符并返回路径证据索引，完整端点证据显式传include_evidence=true；分页固定revision。各类简明报告都支持编辑分析重点、结论和建议；notes仍是对话备注，不作为正文。该共用链路不改变各性质原有公式与数据来源。

AI 是用户与报告之间的翻译官。名称无需规范，AI 可自行绑定授权任务/角色；真正不确定才在原对话给少量选择或接受自定义回答。用户当前或历史给定的参考能量可以使用，即使没有对应气体任务。用户要求的标题、分析重点和风险展示优先于模板。

简明报告（含路径诊断）先显示醒目的“报告重点”：背景、问题、影响各一句短句，有真实待决策项才补一句。assessment使用background/problem/impact/decision，explanation放在后面的“为什么”，只解释支持重点的依据，再接相关图表，不复述摘要或逐项流水账；不把多个分句堆成超长一句。decision为空不显示“无”或空栏。模型工具、人工编辑、正文读回、预览和HTML/PDF共用这些字段与渲染。旧conclusion/recommendation兼容保留；旧报告取已有文字/诊断首句作为摘要，完整旧文字与冻结证据仍在后面的解释区，普通查看不改存档或重新取数。用户要求精简某份报告时编辑原报告的新字段，不只缩短聊天回复。

默认吸附能使用 `adsorption.estimate`（`adsorption.minimum.1.2.0`）：有基底、吸附质、完整构型三个有限能量即可由 Python 计算 `E_ads = E_complex - E_surface - E_adsorbate`。收敛、K 点、来源/结构缺失等在对话中简短总结，不放报告，不阻止初步值；不得宣称正式科学验证通过。缺必要能量时在对话中询问，支持选择和自定义回答，不把报错、缺项清单或补充说明堆进报告。

相对能量、氧空位及已有功函数差值同样默认生成初步结果（`preliminary.1`）：沿用注册配方、Python运算与冻结来源，不要求先通过正式验证。结果标明“初步计算”，缺结构只影响图像；未收敛、参数差异、平台/快照证据不足在对话提醒。氧空位绝对值仍需明确氧参考，差值需共同氧参考条件；未知公式不临时编造。确认组成/任务不对应、目录串用或严重几何异常时仅拦截相关结果，其余可用部分保留。通用数值报告完全缺少可计算结果时直接说明必要缺口，不保存空白完成稿。正式性质面板及高级分步验证入口继续严格检查，不把初步结果冒充校验通过。

报告核心为吸附能和代入公式色块、三个构型的 3D/能量/收敛情况。其他信息按需补充，数据来源折叠，避免向用户堆内部 ID、标签和校验表。

## 以研究目标为导向的断键路径诊断

NEB/断键问题先读取项目计算内容与预期，优先核对端点反应键、片段骨架和 O–Li 接触变化，再看约束和参数；默认 `neb.barrier` 简明报告生成结构诊断，不要求先通过正式能垒数值配方。报告突出关键结论，按问题、影响、解决办法组织，并复用冻结 R2 结构添加距离标注。

端点关联或本地端点结构缺失时，若同一路径已有完整连续的有限映像能量，仍可生成初步离散能垒报告，端点缺口在对话说明；不据此判断断键机制、过渡态或是否适合续算。已确认端点元素/原子映射错误仍拦截诊断，不把它当作普通缺图。

目标反应键、研究范围有歧义时，在原对话确认；回答继续原 AI 对话，已有结构证据保持冻结。两端总能或位移不能拆出形变能/脱配位能；不为填满报告编造数值。详见 [断键路径诊断](reaction-diagnosis.md)。

路径报告展示冻结的映像相对能量与最大力，Python标明采样最高点；已选目标键在表中突出，选择卡直接显示原子编号。骨架RMS明确所排除的元素；约束差异包含候选B/F之外的相关原子。

完整报告、组合和路径专题的 NEB 映像复用巡检详情的 3D 主视图、同步旋转缩略图及曲线/表格联动。生成或明确刷新数据时保存本地已同步的映像 CIF，按编号对应能量；缺结构只显示该映像占位。普通查看、编辑及回答不读取新结构，也不请求当前原子受力。导出 HTML 内联结构、样式、3Dmol 和交互运行时，离线可切换；PDF 保留静态图表和打印时所选映像的结构截图。旧报告需明确刷新或重新生成后才包含映像 3D 数据。

## 三类报告各自保存

| 类型 | 用途与存储 |
| --- | --- |
| project_full | 完整项目报告，沿用旧报告根目录和每项目最新一份的清理语义 |
| composition（R2） | 人工挑选可复用元素，`data/reports/compositions/<项目>/<id>.json` |
| topic | AI 专题，`data/reports/topics/<用户摘要>/<topic_id>.json`，每份独立 ID |

专题/组合不能进入完整报告单份清理逻辑，同一项目多份专题互不覆盖。旧报告保留原配方与证据版本，不批量重新计算。普通编辑不重读当前上游数据；重新生成简明报告产生新 ID，问答补齐产生同一报告新修订。

完整项目报告的独立结构优化任务不设正文数量上限，按原有数据与收敛规则纳入，并生成对应结构、曲线和导出内容。旧快照需重新生成后补齐原先超出6项而被省略的任务；已有注解、隐藏与批注按原规则保留。

## ReportBlock / Evidence 合同

R2 schema `r2.1.0`，实现于 `backend/report_blocks.py`、`report_block_science.py`、`report_compositions.py` 及 `routers/report_compositions.py`。以实际模块和 `/api/reports/blocks/schema` 为准。

- **Evidence** 保存一次科学 payload，包含稳定 `evidence_id`、内容 version、任务/组/项目、来源目录/attempt、观测/文件与 hash_scope、availability、validation 和 freshness。
- **ReportBlock** 保存稳定 `block_id`、type/title、source_refs、白名单 renderer/options；不复制科学数据。标题、排序、隐藏不改 ID；数据变化改 version，不用采集时刻冒充数据版本。
- **Composition/topic** 保存块顺序、分组、隐藏/删除与证据映射。正文、AI 原文、用户编辑和计算结果分离。
- 候选从全部授权任务发现，不能从完整报告 Markdown 反推“没有数据”。名称匹配不证明科学关系。
- 首批 14 类适配覆盖基本信息、参数、能量力、曲线、结构、自由能、NEB、PDOS、Bader、功函数、差分图、比较、分析文字与方法来源；仅解析本地已有结果，不触发 SSH 或分析作业。
- 缺失、未解析、未收敛、隐藏、过期分开表达；不能用 `bool(None)` 把未知变成验证通过。旧快照的正文限额省略状态仍兼容读取。
- 参数对照可选 2–12 个任务；ID variant 由规范任务集合生成。同一 Evidence 可被多个块引用。

## 编辑、修订和新鲜度

简明专题默认先显示结果，进入编辑后可改标题、关键结论、建议、结构顺序和删除。报错、必要缺项和非必要警告留在对话，预览与 HTML/PDF 一致；不删除底层警告、来源和计算记录。旧 `show_warnings` 参数保留兼容，不再给客户报告添加警告栏。

更新必须提供整数 `expected_revision`；冲突返回 409 和当前版本，不能覆盖别人的新编辑。客户端不得写入伪造 Evidence、计算值、renderer 或任意路径。组合只有显式 `refresh_evidence=true` 才更新证据；上游改变时原快照仍保留。

`availability=available/missing/unparsed/unknown`，科学验证和 freshness 另列。参与自动巡检的实时证据采用后端时效规则；不参与或来源无法确认时明确 unknown。不要宣称每种报告都已覆盖全部实时过期检测，具体见各类型的 freshness 实现。

## 导出与交互

站内预览、HTML 下载与浏览器打印 PDF 使用同一保存版本。R2/topic 冻结 PDOS 数据，不能在导出时按 task_id 偷读最新曲线；交互实例按 block_id 定位，避免同任务不同元素串数据。

`src/interactive/reportRuntime.ts` 打包为 `dist/report/report-interactive.js`，由后端内联。部署需一并携带本地 3Dmol 和运行时；缺运行时允许静态降级，不声称交互完整。3D 需要 WebGL，PDF 以已有 PNG/静态图为准，缺图不生成假结构。

所有模型/用户文字转义或用现有安全 Markdown/SVG 路径，禁止模型生成任意 HTML/JS 组件。导出不携带被隐藏/删除块的独占证据。

## 完整项目报告 AI 注解

“AI 批注处理”开关位于**智能报告页**，沿用当前项目字段 `ai_report_notes_enabled`，默认关闭。生成完整报告先整理已有数据、图表和结构；开启AI且选好模型时，继续执行已保存的待处理批注，只修改对应层级及子项。没有批注时不补写分析/论文注解，已完成批注不重复执行；也可单独点击“让AI处理”。缺模型/开关未开、批注执行失败或模块已不存在均在进度对话明确提示；报告页移除批量“生成缺失注解”和人工注解编辑器中的AI生成入口。普通打开报告、开关和人工注解均不付费调用模型；后台生成/批注处理关闭窗口后继续，保留原停止与恢复行为。

报告模型请求默认使用所选连接的输出额度，不再额外压到4096；显式指定预算的调用仍沿用原预算。

“报告进度与对话”窗口显示当前实际处理步骤、完成数量和模型消息，支持恢复连接及显式停止；批量范围可查看全部项目，具体问题回到对应项目继续对话。消息、运行与待审草稿复用原私有 `ai/chat.sqlite3`，分别存于conversations/messages/runs，进度及草稿放原run.snapshot，不另建状态库、队列或执行器，也不新增数据库列。服务重启沿原恢复规则标记中断，保留已有消息和草稿，不重发可能已计费的请求。

已有报告、人工/历史AI注解及旧待审草稿保留；旧草稿仍可恢复、预览、编辑、放弃，人工保存才写入原notes，原2小时凭据、证据指纹、修订检查和恢复入口保留。独立科研分析、旧单条预览接口及明确请求的兼容注解任务仍可用，不再由报告生成顺带触发。完整报告持续对话运行时附加“仅处理已保存批注”的规则，且后端拒绝在该对话调用批量撰写工具；原对话标识/历史不迁移、不重建。

持续对话复用原AI后台工具轮与SSE。`get_full_project_report`读取正文/批注/注解位置，`generate_full_project_report`生成当前项目完整报告，`generate_project_report_notes`保留为独立科研分析的兼容工具（完整报告持续对话中禁止调用），`reply_project_report_comment`把本轮用户原话保存为批注回复，`process_project_report_comment`沿原批注范围与计算规则处理。模型提出必要问题后，用户在同一窗口回复即可继续原报告；不改成新建专题，不新增任意公式或HPC执行权限。项目访问、私有连接、取消及写入前核对沿原权限规则。

## 完整报告模块批注

完整项目报告在章节、类型和任务/路径标题旁提供“批注”，报告上方可查看全部批注。用户可保存要求、回复补充、标记完成或重新打开；普通查看和添加批注不调用模型。处理时复用本项目AI批注处理开关及用户自己的模型连接。

点击“让AI处理”只使用独立的局部编辑Prompt，输入批注/用户回复、目标正文及元素目录、冻结能量和实际结构组成，不夹带项目预期或旧科研注解。支持局部文字替换/补充/删除、直接子模块重排、同路径结构选择，以及相对能量、初步吸附能和中性单O空位形成能计算。计算由注册配方的Python函数产生结构化卡片，包含公式、结果、输入与来源；公式和来源也可单独添加。计算卡片可改标题、补说明或删除展示，文字不能修改确定性数值。新增`card`可添加摘要/说明卡，`presentation`可切换结果卡/紧凑卡/表格与蓝/青/紫配色，并控制来源显示；`layout`对本模块新增卡片排序并设置1至3栏，手机自动单栏。改变外观不重新计算，不改公式、输入或结果；原模块顺序仍用order。模型不能写HTML/JS、替换科学数据或调用HPC；未接入配方返回UNSUPPORTED，不临时编造计算。

氧空位基于报告冻结结构确认实际组成恰好少一个O；用户明确给定O₂能量时Python除2得到μ_O，明确每O化学势则直接使用，沿用原单位换算和原话审计，不要求新建气体任务。最新回复优先旧参考。同一报告较早批注中用户明确给定的氧参考会进入当前事实目录，无需再确认；“沿用”保留原用户来源，“沿用-8.3”或短数值回复从已有明确用户参考继承角色/单位，并保存当前原话及继承依据。多个不同候选仍需明确，AI旧回复不能单独提供数值事实。计算器先采用已确认的用户参考，再处理模型绑定；模型临时引用失效不会把已知参考误报为缺能量。已知组成错误/带电或缺必要结构只阻止对应组，保留其余可成立结果；弛豫坐标变化、电荷/位点/条件未知不能冒充正式验证，结果标为PRELIMINARY。负形成能保留。核验状态/检查/警告继续留在结构化数据；页面、Markdown、HTML和PDF默认不输出“电荷态、位点对应、晶胞与计算条件仍需核实”等核实提示，仅用户明确要求时才通过presentation.show_warnings展示。成功只回复一句实际修改确认，缺数据只问具体缺口，不默认生成科研审查。

结构筛选复用原路径表格、台阶图、3D视图和切换窗口，在线正文、静态图及单文件导出使用同一选择。模块重排后按原图路径对应已有隐藏项，避免把隐藏状态移到另一张图。原“结果分析/论文参考”及手工编辑继续保留；本批注生成的补充文字可在重新打开后改写，重复处理不会不断追加同一段。

新增卡片以稳定元素ID保存在content[target].elements，原正文有局部编辑ID；有效报告的review_elements为页面和导出的共同结构化来源，页面卡片HTML与HTML/PDF共用渲染器及响应式样式：大号结果数值、能量输入、数学公式、氧参考和可展开来源；多体系有独立结果块及比例条。打印保留输入/结果并展开来源，Markdown从同一元素按卡片顺序导出。现有卡片读取时直接采用新呈现，不改存档或重新调用模型。AI开关只刷新批注处理设置，保持图表与3D挂载。

批注、AI回复、来源及状态保存在原 `edits/<report_id>.json` 的 `review`（`report.review.1`），不另建聊天或任务库。history保留动作、模型、修订及修改前展示内容；重复执行同一批注重用元素ID。AI结果实际写入后才标记完成，已完成项不重复调用模型；需要补充时保留回复与已能完成部分。版本冲突返回409，取消或失败保留原批注。报告重新生成后不套用旧版展示修改/计算值；待处理批注按原模块的章节及完整标题路径唯一对应到新版，再用新版事实执行。能对应当前模块的已有旧批注也可继续处理，无法对应或有歧义时保留原文并明确提示重新添加，不猜测目标。

批注仅在系统前端展示，HTML、Markdown和打印PDF不携带批注、回复或状态；AI生成的正文、解释、计算结果及原有交互正常导出。本链路针对完整项目报告，独立专题/人工组合沿用各自编辑器。来源中保存用户原话供追溯，导出仅显示给定能量及原单位，不拷贝整段批注。调查调用链、实际数据配对、验收与遗留见[批注审计](report-review-audit.md)。

## 历史问题与维护边界

PMS 曾只停在 prepared，候选匹配又遗漏 `PMS@model1`，导致空草案；这些问题已修复。默认简明工具直接构建并保存，无需模型连续跑 prepare→plan→write→save；高级旧流程仍存在，不能当作默认必经步骤。正文中的 DSML 等伪工具指令不执行，也不能冒充保存成功。

相关源码：`topic_simple.py/topic_tools.py/topic_reports.py/adsorption_minimum.py`；前端 `src/components/reports/TopicReportEditor.tsx`、原 Report 页面和报告交互运行时。只改涉及的层，必要验证参考 `test_minimum_report.py`、`test_topic_reports.py`、R2 测试和对应浏览器用例，不为每次改动重跑全部报告套件。
