# 构建提示词：巡检驱动的项目托管最小版本

你正在开发 https://github.com/chelair/vasp-management-system 。

请基于当前代码完成“巡检后按优先级与资源情况自动推进计算”的最小可运行初版。先读 AGENTS.md 用户最新开发准则和 `agent-upgrade/managed-compute-audit.md`，核对源码后直接实现。不要重造系统，不要求用户规范输入，不做无关备份/全量测试。当前授权是开发和隔离验证；不要自动部署、启用真实托管或提交真实 HPC 作业。后续若获准推送，直接 main。

## 一、交付结果与首版边界

用户在现有 AI 工作台说：

“这个项目周五先交 model1 的阶段报告，把它放最高；有输入的任务帮我接着跑。允许的几个 CPU 队列里优先选较容易开跑的配置，付费队列不用。正常续算直接做，受力振荡、反复续算没改善和异常再请 AI 判断。”

AI 能理解项目、模型别名、时间和资源偏好，自行查询实际任务；真正不确定时复用现有对话选择卡和自定义回答。将计划、任务优先级和后端资源规则持久化，用户有简单手动调整、暂停/恢复/结束入口。用户只需一次授权范围/额度，授权内自动运行，不逐次弹窗审批。

首版针对已有模型和已准备输入的任务：安排多个已有任务的先后/明确依赖，自动提交 ready 任务、OPT 正常续算和少量异常修复。不开发结构建模、通用 DAG、多智能体、完整自动 OPT→STATIC→DOS 输入构建，不为凑闭环随意创建科学任务。缺输入时说清缺什么。

## 二、强制复用

- 现有私有模型连接、思考深度配置、项目会话、SSE、历史与权限，不另建聊天。
- `inspection_runner`、`automation/events.py`、现有后台执行设施；不增加独立高频轮询。
- `automation/actions.py`、`gateway.py`、`ledger.py`、预算/任务族锁/幂等/UNKNOWN 对账和原审计，不另建提交系统或第二套事实状态。
- 现有前端提交、续算、停止、脚本写入所调用的后端业务核心；后台直接共享核心服务，不模拟点击浏览器、不另写 bsub 提交器。
- `cluster_probe` 的共享采集、`cluster_status` 的节点队列映射、已有错误库、力曲线、参数草稿和 task context。
- `src/utils/vaspLsf.ts` 成熟八段模板。补后端受控渲染服务并让前端可复用；不要让模型自由写 Shell。以一个权威模板/规范或必要的一致性检查防止两套模板漂移。

## 三、形成真实闭环

用户说明 → AI 规划/规范化规则并保存 → 每轮巡检完成 → 对账/场景过滤 → 必要时一次 AI 决策 → 汇总 ready 动作 → 按优先级分配资源 → 确定性生成提交脚本 → 现有续算/提交 → 后续巡检验证。

保留逐任务事件对账，但资源调度以整轮完成后的候选集合为单位，不能按任务在项目库里的顺序抢先提交。同轮失败项目不用旧证据自动推进。扫描已授权 pending/ready 任务，弥补全局巡检跳过 pending 导致的首提缺口。单任务巡检也可刷新相应候选，并用同一调度入口。

规则判断和模型调用分开，模型不得阻塞事件接收/其他任务对账。后台任务状态持久化，重启先对账；内存队列不是唯一事实来源。已托管任务与旧自动化只能有一个执行归属，不能互相绕过或重复续算。

## 四、AI 有业务决策权，日常流程不依赖 AI

1. AI 可按用户说明制定已有任务的下一步计划、设置阶段交付时间和优先级、写入允许范围内的资源规则，不只输出建议。
2. 普通排队、运行且趋势正常、已收敛、授权内正常 walltime/软结束续算由后端规则直接处理，不调用模型。
3. 场景识别由 Python 完成，首批覆盖：离子受力振荡/停滞、累计 RUN 多天且多次续算仍无改善、电子未收敛、已知 VASP 报错、反复相同失败、明显超长 PEND。阈值可配置；用曲线窗口/有效步数/改善率，不能仅一次力上升或只看目录数量。RUN 与 PEND 时长分开，次数按真实尝试统计。
4. 不得将所有 ACTIVE 状态直接提前 return，导致运行中异常永远进不了识别。
5. 给 AI 的是紧凑事实摘要、触发场景、当前计划、必要小段日志、可行动作/参数范围和剩余额度。默认单次决策、约千字级输入；不足时最多补查一次限定证据。记录调用数、token 和去重/跳过原因；相同事件未出现重要变化不反复请求，设置冷却与每轮调用上限。不要把整项目报告、全部上下文/历史/OUTCAR 发给模型。
6. 模型应能真正选择继续观察、有界续算、选择适用的参数修复预设、改后续任务顺序或暂停求助；不再限定“同意唯一候选或暂停”。首版选少数有依据的 OPT 修复参数/预设，写清适用证据和边界；未知修复可以建议，不能假称已执行。
7. 运行中需要中断时，区分“暂停托管”和“停止作业”。在已授权停止范围内，复用现有停止核心，LSF 确认终态并核对可用输出后再创建续算/重提；未授权停止则继续监测并请求用户介入。不能把 bkill 请求受理当成已停止，不能同时跑两份。
8. 模型失败保留原计划，普通确定性动作仍能运行；对需要该次决策的异常保留等待状态/明确原因，不盲目重算。

## 五、优先级与资源是后端两层决策

项目默认优先级 + 任务覆盖 + 阶段交付时间即可，不需要复杂排程系统。用户说“这个任务这周交付，先做”时 AI 应直接保存更新；不通过修改整个项目 deadline 来假装支持任务优先级。保存来源原话、解析后的截止日期/时区、理由和生效范围，缺省“阶段报告”不能自动编造额外计算依赖。

保留手动优先级/锁定入口；明确锁定时 AI 不覆盖，用户新指令可解锁。已授权的同一用户多个项目共享额度时统一排候选；其他用户任务内容不进入模型。

先决定哪个任务先分配，再为它选资源方案。资源方案包含 queue、总核数、每节点核数/ptile、预计节点数、walltime；是否固定节点名按明确配置，默认不强制钉死主机。

后端完成：

- 使用真实且足够新的队列、节点、用户额度快照；缺关键字段/过期/模拟数据只等待或刷新，不作真实自动提交依据。同轮同服务器复用一次采集，执行前重查必要额度。
- 在已授权队列和核心/核时/并发上限内枚举少量配置，先过滤关闭/不兼容/超时限/内存不足/核数布局不合法的方案，再评分。
- 评分考虑队列 PEND、满足 ptile 的节点分布、可用核数、挂起风险、付费成本和明显过量申请；有可靠历史时再考虑运行效率。不能仅按总空闲核数判断多节点可运行，也不能始终抢最大核数。
- 返回评分分项、选择原因、快照时间。评分是启发式，不谎称精确预测排队时间；优化目标兼顾尽早完成与少浪费核时。
- 原话“免费优先/禁止付费、优先短队列、最多两节点、某队列禁用”等由 AI 转成受校验的规则字段并持久化；规则匹配和评分不调用 AI。缺省先提供可用规则，超出现有语法时明确说明，不能伪装保存成功。
- 规则作用于该用户授权范围；改变集群全局策略仍按现有管理员权限处理。明确的用户写入指令可直接保存，无须每次再次批准。
- 一轮内对已选方案做额度占用/预留，后续任务看剩余容量，防止多个任务同时挑同一批空闲核。包括已有人工作业的账户限额；没有适合资源时可解释地等待或按配置进入队列，不忙重试。

## 六、接通已有阻塞，不重写底座

- 授权兼容原 queue，同时支持同一服务器允许的 CPU 队列集合；不同计费/资源池按原预算语义分别约束，不让模型扩大预算。
- 将脚本资源计划和生成版本纳入动作快照，调整原 OPT 对 vasp.lsf 必须原样不变的检查：只接受已验证资源计划生成的变化，不直接关闭指纹复核。
- 支持现有软结束模板的 `-wt/-wa`，识别正常 STOPCAR 软结束后的合法续算；站点生成器与资源解析器必须一致。
- 托管生命周期使用持久授权，而非要求浏览器会话长期在线；登出不等于撤销托管，显式撤销仍立即阻止新动作。授权绑定用户/项目/动作/资源，账户禁用或归属变化仍生效。
- 正常观察不耗尽 30 步修复额度；正常 walltime 接力与异常修复分别计数，但都遵守总体提交/核时上限。明确保存预算耗尽后的等待/暂停原因。
- 常见固定原子 OPT 按实际可动分量判断力，不能直接丢弃 F 约束或宣称其全部自由；超出支持的结构格式明确标注。
- 参数改动进入已有草稿和新 conN；不覆盖用户已有未应用修改，不把人工草稿自动全量套用。保留 CONTCAR→POSCAR 的已有续算语义，不建新模型。
- 执行前再验证当前授权、任务/目录/作业身份、无活跃冲突和额度。bsub 成功响应丢失一律对账，不盲重提。优先级不会自动改变 HPC 调度器自身优先级，也不擅自取消排队/运行作业来迁移。

## 七、前端只做最小必要入口

在原 AI 工作台/项目与自动化入口加简明托管状态：当前目标、下一步、为什么等待、最近做了什么、需要用户处理什么；可手动调优先级、暂停/恢复/结束。配置不足时一次给少量选项，可自定义回答；不让用户填 task_id、JSON 或逐任务脚本。

资源枚举/评分在后端，不开发复杂资源排程页面。托管计划、动作、规则版本、证据和模型摘要复用原存储/审计；不用第二套任务状态代替原作业真相。

## 八、只做必要验证，完成初版即停止

复用现有 Mock SSH/LSF、模型和网关夹具，用少量组合场景验证：

1. 一句话完成计划/优先级/资源规则落库；人工入口能覆盖/锁定。
2. 同轮高优先任务先分配，资源评分与额度预留正确；规则定完后不为评分调用模型。
3. 正常状态零模型调用；合法软结束→新 conN→受控脚本→提交→下次巡检验证。
4. 振荡/多日多次无改善/错误由规则命中，AI 有可选处置；同事件不反复花 token，运行中停止必须等终态。
5. 重复事件、超时/重启、模型失败、预算不足/资源过期不能重复提交；浏览器离线与托管撤销语义正确。
6. 一条隔离端到端串起用户说明、巡检、优先级、资源、模拟续算提交和结果回显。

只跑直接相关测试；若改前端则做类型检查、隔离构建和一条必要交互验证，产物放 /tmp。不要为文案/低影响修改写镜像测试，不跑无关报告全套回归，不备份服务器计算文件。没有真实 HPC 授权就不进行真实提交验收。

交付简短说明：实际可运行路径、复用模块、必要验证结果、首版尚不支持的情况，以及如何一次性开启/接管。更新开发交接文档。明确区分“隔离验证通过”与“真实项目已验证”，不要只交提示词修改或假数据演示。完成后停止，不自动部署生产。
