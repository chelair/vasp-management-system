# 自动化、受控执行与单 OPT 循环

维护日期：2026-10-20。合并原阶段 0/1/2 和参数证据交接。这里只描述现有执行能力，项目托管 M0 与尚缺链路见 [托管现状](managed-compute.md)；接口见 [API](../API.md)。

## 执行路径

巡检归档 → `automation.events` → 对账/旧规则匹配/已存在 OPT 循环 → `automation.scheduler` → 受控网关 → 原 jobs 核心 → LSF → 后续巡检验证。

自动化规则在 `data/config/rules/`，设置在 `data/config/automation.json`；全局暂停、dry_run、冷却、次数/失败限制和五态审计已经实现。旧自动化管理接口仅 admin，不能把它直接开放给普通用户作为项目托管。

`automation.actions` 的 ActionSpec 和人工 HTTP 入口共享 `routers.jobs.core_submit/core_continuation/core_create_frac` 等业务核心；不要另写提交命令或在后台模拟浏览器点击。

## 授权与预算

`data/agent_execution.json` 为授权、动作、预留额度与 OPT 运行的持久台账；文件坏了阻止执行，不按空状态重建。复用现有进程/文件锁和原子替换；当前单 writer 部署不等于整个项目库已支持任意多进程。

新自主执行默认关闭。授权绑定 owner、Agent、项目、服务器目标指纹、原始任务根目录/类型、动作白名单、单 CPU queue 和预算。首次启用后即受托管约束，暂停不能让旧规则恢复成预算旁路。

预算包括最大活跃作业、总提交、失败重试、核时、walltime 和核数；后三项需明确配置。核时预留为申请核心数×walltime，结束后现有 consumed 值仍按保守上界，不能作为实际计费。

执行前重新查身份/权限、任务族、当前目录和 LSF。提交/续算子任务共用任务族锁；continuation 的 follow_up submit 使用实际子任务，并继承同一预算。

## 幂等、未知结果和停止

- 相同意图用稳定幂等键；相同键改参数拒绝。换键也不能绕过未结束/UNKNOWN 动作。
- 实际副作用前先落盘。bsub 已成功但 HTTP/SSH 响应丢失时先查询并绑定原 job，不直接重提。
- 重启恢复先对账，未知副作用不重放。找不到历史 LSF 不等于从未提交，也不代表科学收敛。
- 人工确认旧作业结束入口在提交报错弹窗；绑定旧 job/目录/服务器，重查无活跃冲突后保存审计，不能自动确认或立即重提。
- 当前人工停止依据 bkill 成功返回更新本地状态与台账，不额外轮询 LSF；不把停止当科学收敛。再次提交仍实时检查活跃作业，发现原作业还在运行会同步回 running 并拒绝重提；旧对账不覆盖新 job。
- `dry_run` 不建远端文件、不预留或提交。权限/审计/持久化失败不能继续自动副作用。

## 单 OPT 有限循环

通过 `/api/agent-execution/opt-runs` 创建、step、pause/resume/close。仅原始已有输入的 OPT；使用现有私有模型连接可选审阅。创建并不立即提交，已有巡检事件可推进。

| 状态 | 当前行为 |
| --- | --- |
| 初次待提交且输入合法 | 经网关提交 |
| LSF 排队/运行/挂起 | 等待，不调用模型 |
| 明确 TERM_RUNLIMIT，证据完整 | 有界续算并提交 |
| NSW 耗尽 | 已授权增量/上限且力改善时增 NSW 后续算 |
| SCF 失败、新错误、无改善、证据/状态未知 | 暂停并记录原因 |
| 电子/离子、正常退出和 LSF 交叉验证通过 | 结束基础循环；科学精度仍未证明 |

模型当前只可同意确定性 candidate 或改为 pause，不能自由修复。运行中指标分析在现有早返回之前尚未接通。默认 max_steps=30，普通等待也累计；max_repairs 默认 1，正常续算也占 repair。启动绑定会话，过期/撤销会影响后续执行。这些均是后续托管执行接通的实际缺口，不能误报为已解决。

诊断只读补采最新 conN 的限定文件并核对 job/输入/输出时间，OUTCAR 等取有界尾部。当前适用范围限制 IBRION=1/2、负 EDIFFG、显式关键参数和部分 VASP5 格式；含 F 的约束结构不能直接按现有全自由力逻辑判定。原输入镜像不作为旧尝试的完整科学证明。

暂停/关闭循环不停止远端作业；未结束循环包括暂停态，通用动作入口不能绕开它的策略。人工草稿不能被自主修复偷偷全量应用。参数只进入新 conN，CONTCAR→POSCAR 与 WAVECAR 移动沿用原业务语义。

## 脚本兼容和后续扩展

原预算解析器只支持静态 CPU LSF 子集，尚不接受前端默认软结束 `-wt/-wa`；单 OPT 提交前又要求 vasp.lsf 与来源指纹不变。M0 的后端脚本渲染/预览已有独立解析验证，尚未替代旧网关校验。接通时要统一资源计划快照和白名单，不删安全核对来绕过限制。

基础测试在 `test_agent_gateway.py/test_opt_loop.py/test_automation_baseline.py`，含 Mock SSH/LSF、响应丢失、重启对账、父子锁和预算。按本次改动选必要用例，独立临时 DATA_DIR/密钥；隔离通过不是实际项目无人值守验证，真实 HPC 写入需有相应授权。
