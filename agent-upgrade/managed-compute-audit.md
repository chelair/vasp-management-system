# 巡检后项目托管：现状审视与最小链路

日期：2026-10-20。依据当前 main 源码、测试用例定义及本地生产配置只读检查；没有运行测试、调用付费模型、连接 HPC、创建授权或提交作业。本文是审视与构建说明，不代表功能已经实现。

可直接交给开发助手的任务见 [最小版本构建提示词](managed-compute-mvp-prompt.md)。

## 1. 当前实际启用情况

- `data/agent_execution.json`：自主执行 `enabled=false`，授权 0，OPT 托管运行 0。台账有 12 条动作记录，不能把这些普通执行记录当作 AI 项目托管验收。
- 旧自动化开启且非 dry-run，4 条规则中启用 1 条；定时规则总开关关闭。
- 自动巡检相关字段未显式设置，按源码缺省值启用、每 2 小时检查一次；集群缓存 300 秒。
- 页面上的“AI 报告撰写”仅是报告开关，并非项目计算托管。单 OPT 托管有后端 API，前端没有创建授权/启停 OPT 循环的完整配置入口。

## 2. 与用户五项要求逐项对照

| 用户希望 | 现有能力 | 实际缺口 |
| --- | --- | --- |
| 理解计算目标，规划并自动续算/提交 | 单 OPT 初始提交、walltime 续算、有界 NSW 增长；已有业务提交/续算入口 | 没有按项目目标安排多个已有任务的计划；聊天不能执行；尚未有真实项目无人值守验收 |
| 阶段性交付任务最高优先，AI 能改、人工也能改 | 项目交付日期和工作量推导四象限 | 不是计算调度排序；没有任务级阶段截止日期/优先级覆盖；AI 无写入工具，前端优先级只读 |
| 后端按队列、节点、核数方案评分并生成脚本 | 共享资源采集、节点队列映射、blimits、前端成熟 LSF 模板、上传脚本与提交 | 没有后端候选评分/调度；脚本模板目前在前端；单授权固定单队列；没有按共享额度竞争资源 |
| 巡检触发，规则先过滤，少用 token | 巡检逐任务事件、确定性 OPT 诊断、仅修复候选调用模型 | 逐任务即推进，缺少整轮候选排序；模型阻塞同一个事件消费线程；没有项目级异常事件去重/调用额度 |
| 后端识别振荡、多次续算且多天、异常，再交 AI | 力曲线、错误库、续算关系、巡检/动作历史；报告有多次续算风险规则 | 未接入运行中异常干预；没有联合时长/次数/改善率识别；错误通常直接暂停，不到 AI |

## 3. 真实调用链及证据

1. `backend/inspection_runner.py:675`：归档后非阻塞发布巡检事件；全局巡检尾部才作废/预热资源缓存（约 698 行）。
2. `backend/automation/events.py:38`：将整轮结果拆为逐任务事件；`_handle`（92 行）先做台账对账，再 `opt_loop.inspection_event`，最后匹配旧规则。事件线程逐个处理，没有按项目紧急度统一排序。
3. `backend/automation/opt_loop.py:287`：单任务采样→诊断→确定性计划→可选模型审阅→网关执行→验证。`inspection_event`（504 行）只推进已创建的运行，没有项目规划器。
4. `backend/automation/opt_loop.py:146`：确定性动作限于 wait/finish/continue/increase_nsw/pause。`validate_decision`（178 行）只允许模型同意既定动作与参数或暂停。它是方案审阅者，尚非故障修复决策者。

## 4. 必须在初版接通的冲突

- **无人值守不是打开现有开关就够。** OPT 绑定启动浏览器会话；会话过期或撤销时停止新动作（`opt_loop._authorize`、`gateway.live_actor`）。关闭页面本身不停止，但长期会话过期不应意外决定托管寿命。复用持久委托授权并明确撤销，而非要求用户一直在线。
- **普通观察耗尽步数。** `max_steps` 默认 30（创建时最多 100），每次观察包括等待都累计。当前每两小时一次，约 60 小时就可能暂停；不是 30 次实际修复。应把观察、提交、修复次数分开。
- **正常续算也占“修复次数”。** 当前 continue/increase_nsw 都累计 repairs，默认 1；不能不区分正常 walltime 接力与异常反复重算。
- **运行中异常被提前跳过。** `opt_evidence.py:126` 先将 ACTIVE 全部归 running，尚未分析力/报错。需要在不重复提交的前提下独立分析运行中指标。
- **软结束链路不闭合。** 前端 softKill 默认 true，模板生成 `#BSUB -wt/-wa`；`budget.parse_lsf` 白名单不接受它们。且 STOPCAR 导致的正常退出不一定是 LSF `TERM_RUNLIMIT`，旧诊断也可能不归 walltime。必须做站点脚本兼容和软结束证据判断，不能直接删除软结束保护。
- **多队列和脚本变化被原策略拒绝。** 授权只接受一个 queue；预算要求完全相同；OPT 提交前要求 `vasp.lsf` 与源证据指纹相同。应增加合法资源计划快照并校验其生成结果，而不是绕过校验或临时改远端脚本。
- **整轮排序与首提任务缺入口。** 全局巡检跳过 pending/archived；只沿用逐任务事件，既无法统一排序，也无法启动从未运行的已准备任务。整轮结束应读取授权范围的 ready/pending 任务，并保留单任务事件对账。
- **事件消费可能被模型阻塞。** 当前 OPT `step` 同步调用模型，超时可到 90 秒。复用现有后台执行设施隔离耗时决策，不让某任务拖住其他任务对账/事件接收。
- **暂停托管不等于停止 HPC。** 旧 control.pause 明确不停止远端作业。若首版要在运行中真正减少浪费，必须显式区分观察、暂停托管、停止作业；只有授权停止时才经现有 stop 路径执行，并等 LSF 终态后续算。
- **适用范围比较窄。** 单 OPT 科学诊断目前限制 IBRION=1/2、负 EDIFFG、显式参数等；`structure()` 对包含 F 的约束结构拒绝自动判断，而表面模型常用固定原子。首版至少正确按自由分量处理常见 Selective Dynamics，不能直接删检查或假称现有实现已支持。

## 5. 建议的最小可运行链路

用户一句话说明目标、交付时间和资源偏好 → AI 一次性理解并写入项目托管计划/优先级/规则 → 每轮巡检结束 → 后端对账与确定性场景识别 → 普通等待/正常续算由规则处理，少数异常交 AI 选择下一步 → 汇总可执行候选 → 按任务优先级与资源方案评分分配额度 → 用后端受控模板生成脚本 → 复用续算/提交核心 → 等下一轮验证。

初版只覆盖已有模型、已准备输入的任务和 OPT 续算；可以把多个已有任务放入简单有序计划及少量明确依赖。自动建模、自动生成一整套 OPT→STATIC→DOS 输入、复杂工作流和运行中作业迁移留待后续。这里的“规划”必须能驱动已存在任务的执行，不能只生成说明文字。

AI 应拥有真实业务选择权：根据用户指令改优先级、保存资源偏好、选择可执行的下一任务，以及在异常时选择有界修复方案。身份/范围/预算/幂等由后端保障；不再限制为只能附和唯一 candidate。已授权范围内不逐动作要求人工确认。

资源评分只能依据当前快照给出启发式排序，不能把空闲核数或队列 PEND 数称为精确等待时间。任务紧急程度决定先分配给谁；资源方案评分决定它用什么配置，不能用一个混合分数让低优先任务抢先。没有经验证的并行效率数据时，不承诺更多核一定更省钱/更快。

只在必要时问用户：目标/任务确有歧义、授权缺关键范围、方案超出已授权资源/修复范围。其余自动推进，并给出“做了什么、为何等待、哪里需要你”的简明记录。

## 6. 验证和边界

- 本轮只读审视，未重跑历史测试；测试文件定义证明已有离线覆盖设计，不能当作本轮测试通过或真实托管成功。
- 重点可复用 `tests/test_agent_gateway.py` 的重复提交/响应丢失/预算/父子锁/对账用例及 `tests/test_opt_loop.py` 的巡检闭环与模型边界夹具。
- 未来首版只补该链路关键测试、一次隔离端到端验证和必要前端构建。未授权前不用真实 HPC 做写入验收，不做无关全量回归或计算文件备份。
- 本轮没有部署、重启、推送或改变任何生产规则/开关。完成审视后停止。

## 7. 实现进度（M0，2026-10-20）

按第 5 节的最小链路先做"不打开执行面"的一半，托管执行仍未实现：

- **已实现**：计划/任务级优先级/阶段交付/资源规则落库与版本冲突（`backend/managed_plan.py`，`data/managed_plan.json`）；候选排序（人工覆盖 > 阶段优先级 > 默认）；已授权队列内的资源方案枚举与确定性评分，模拟/过期/缺失快照一律等待（`backend/managed_schedule.py`）；`vasp.lsf` 后端渲染与提交前检查，并与前端模板做漂移测试（`backend/vasp_script.py`）；AI 结构化工具 `create_managed_plan` 等（`backend/managed_tools.py`）；只读 HTTP 接口与前端"项目托管"页。
- **未实现（仍是本文件第 4 节的阻塞项）**：整轮候选汇总与统一调度入口、首发提交/续算/停止的执行接通、运行中异常识别顺序、事件线程与模型解耦、多队列授权 schema、`-wt/-wa` 进入预算解析、`max_steps` 与 repairs 分账、旧自动化与托管只能有一个执行归属。
- **验证**：隔离测试 30 项 + 一条真实浏览器验收；执行开关仍关闭、零授权，未部署、未改生产配置、未提交 HPC 作业。隔离验证通过 ≠ 真实项目已验证。
